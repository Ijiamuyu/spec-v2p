### 3.3 分项解读

#### LUT：~65%（中位数估算，范围 115K~150K，占用率 56%~74%）

评估处于**可行范围**，中位数 ~65% 低于 75% 安全线，上限 ~74% 仍在安全线内，时序收敛压力较小。

**主要来源**（按占比排序）：

| 子系统 | 中位数估算 | 占比 |
|--------|-----------|------|
| AP（四核 RV32 SMP + Debug） | ~48K | ~36% |
| NPU（Coral） | ~36K | ~27% |
| LSIO（含 Ethernet / DMA / SD / PWM） | ~21K | ~16% |
| FSI（RV32 + 安全外设 + PMU） | ~14K | ~11% |
| 系统基础设施（含 AXI 互联） | ~13K | ~10% |

**最大不确定性来源**：
- **VexRiscv-SMP RV32 ×4（全表最大不确定性）**：每核**基础部分**（RV32IMA + MMU + Sv32 + S 态 + 缓存）有**上游 Artix-7 实测**支撑 —— `linux balanced` 配置仅 **2883 LUT**（Artix-7 与 Kintex-7 同为 28nm LUT6、同 BRAM 架构，LUT 数可直接迁移）。本配置额外含：
  - **C 扩展**（解压器，很小）
  - **每核内置的全流水 F/D FPU**（`externalFpu=false`；支持 add/mul/fma 每周期出结果、radix-4 除、radix-2 开方）——上游未公布其面积，但从生成物看 `FpuCore` **9081 行** vs 整核 `VexRiscv` **10440 行**，FPU 是**核内最大的单一模块**

  故单核区间取 **6.5K~9.5K**（实测基础 2.9K + C + FPU），四核 **26K~38K**，加一致性/PLIC/CLINT/Debug 约 6K~8K，AP 合计 **32K~46K**（本表取 ~48K 偏保守）。
  ⚠️ **建议优先综合单核（含 FPU）锁定该项** —— 成本最低、收益最高。
- **Coral NPU**：标量+向量+矩阵 MAC 三合一，控制逻辑开销使实测 LUT 比算术估算高 15%~25%，中位数约 **36K**。
- **AXI 互联**：6 主多从架构，含 CDC 异步 FIFO，合理区间 **8K~10K**，中位数约 8K。

#### BRAM：~72%

片上存储器为主要消耗：

| 项目 | BRAM36 | 占比 |
|------|--------|------|
| SYSTEM SRAM 672KB | ~168 | ~38% |
| FSI 私有 SRAM 128KB | ~30 | ~7% |
| NPU ITCM/DTCM 与内部缓冲 | ~48 | ~11% |
| AP 缓存 / PLIC / CLINT / Debug | ~38 | ~9% |
| LSIO 外设缓冲 | ~8 | ~2% |
| BootROM 28KB | ~8 | ~2% |
| AXI Interconnect FIFO | ~8 | ~2% |
| DDR3 MIG / 余量 | ~13 | ~3% |
| **合计** | **~321** | **~72%** |

两处关键换算（易错）：

1. **SYSTEM SRAM 672KB 需 168 块**：BRAM36 虽有 36Kb，但**数据宽度为 32/64 位时每块只能用 4KB**（每字浪费 4或8 个 spare bit）。
   `672KB / 4608B (位完美 4.5KB/块) ≈ 149`，而 `672KB / 4096B (实际 4KB/块) = 168`。
2. **L1 缓存 ~24 块**：每 cache 8KB 数据（512 深 × 8 字节 × 2 路）+ tag，约 3 块；每核 I$+D$ ~6 块；4 核 ~24 块。
   （若 tag 改用分布式 RAM，可降至 ~16 块。）

余量 **~124 个 BRAM36（约 28%）**。BRAM 是**最紧张的资源**，后续扩展需优先从 DDR3 寻空间。

#### DSP：~19%

DSP 主要被 Coral NPU 矩阵 MAC 脉动阵列消耗（~130 个），其余子系统合计 ~29 个。余量 ~681 个，**非常充裕**。

## 4. 评估结论

| 维度 | 评估 | 说明 |
|------|------|------|
| **资源充足性** | ✅ **可行** | LUT ~65%（范围 56%~74%），BRAM ~72%，DSP ~19%，均低于 75% 安全线 |
| **时序收敛** | ✅ **压力较小** | LUT 中位数 ~65% 占用下，-2 速度等级跑 **100MHz 系统时钟无压力**（上游 Artix-7 实测 MMU 版 151MHz，Kintex-7 更快）；若 DDR3 跑 400MHz（800Mbps）、NPU 跑 150MHz，需提前做物理约束和分区布局 |
| **瓶颈资源** | **BRAM（非 LUT）** | 片上 SRAM（SYSTEM 672KB + FSI 128KB + NPU 40KB）占 ~55% BRAM，余量仅 ~28%，是**首要约束**；LUT 反而有 FPU 面积未知带来的不确定性 |
| **最大不确定项** | **AP 每核 FPU** | 全流水 F/D FPU 上游无公开面积数据，而它是核内最大模块；已包含在 32K~46K 区间内，建议优先实测 |
| **扩展余量** | 充裕 | PCIe / CMT / DSP / I/O 均有大量余量（GTX 未被千兆以太网占用） |

### 建议

1. **验证优先级**：先单独综合 **单核（含 FPU）** —— 这是全表最大不确定项，一次即可锁定（成本最低）；其次综合 **4 核簇 + AXI 互联**，这两项占 LUT 总量近 50%
2. **并行推进**：拉取 Coral NPU RTL，在 Vivado 中做综合测试工程，获取真实 LUT/DSP/BRAM 数据
3. **BRAM 规划**：当前 ~72% 占用中片上 SRAM 占绝大部分，余量仅 ~28%；后续若要加缓存、扩 NPU 缓冲，优先把非实时数据搬到 DDR3
